## 지켜야 할 것
- 테스트가 통과해야 배포·출시한다(백엔드 `./gradlew test`, 앱 `flutter test` + `node tool/gates/check_analyze.mjs`). 마이그레이션이 있으면 운영 DB 를 먼저 `~/backups/` 에 백업한다. 배포 절차와 함정은 메모리(liftupai-local-eval-and-shots, liftupai-coach-agent)에 있다.
- 앱 출시는 심사 중인 버전이 있으면 커밋까지만 하고, 승인 뒤에 낸다. 버전은 pubspec 의 다음 번호.
- 다른 세션이 고치던 파일(커밋 안 된 변경)은 건드리지 않는다. 백엔드 `docs/` 는 다른 세션 것. `git status` 로 먼저 확인한다.
- 비밀값은 출력·커밋하지 않는다. 키는 `kw run <이름> --` 로만 쓴다. 운영 서버에는 프로그램을 설치하지 않는다.
- 절대 하지 않는 것: 결제수단·비밀번호 입력, 새 계정 만들기, 돈 송금·투자, 사용자 데이터 대량 삭제, CAPTCHA 우회, 실버리즘 등 다른 앱 작업.
- 사용자에게 가는 대량 발송(전 사용자 푸시·이메일)은 하루 한 번 이하, 이미 만든 안내 장치(app_versions 권장 업데이트 등)를 우선 쓴다.
- 확신이 없거나 되돌리기 어려운 일이면 더 작은 버전으로 먼저 하고 결과를 본다.

## 보고 형식(Slack mrkdwn, 대표 일일 리포트와 같은 톤)
- 굵게 `*텍스트*`, 목록 `•`, `#` 제목·마크다운 표·`**` 금지. 숫자 비교는 `3명 (어제 1 · 7일평균 0.6, ▲)`.
- 메인 메시지(1,500자 이내):
```
:muscle: *리프트업AI 대표 보고* — {MM/DD (요일)}
🟢|🟡|🔴 *목표 진척* — MRR ₩{x} / ₩10,000,000 ({%}) · 유료 {n}명 · 체험 {n}명
*퍼널(24h · 7일)* — 실가입 · 첫 세트 · 결제 화면 · 체험 시작 · 결제
*오늘 한 일* — 1~3줄(결과 중심, 배포·출시는 버전/커밋)
*내린 결정* — 무엇을 왜(근거 숫자)
*위험·이상* — 없으면 "없음"
_상세는 스레드에 →_
```
- `---THREAD---` 뒤 스레드: *PO 리포트*(North Star·유입·활성화·참여·리텐션·수익·품질 — 대표 일일 리포트의 앱별 형식), *인사이트* 2~3개(사실/추정 구분), *다음 액션* [P1]/[P2] 3~5개.
